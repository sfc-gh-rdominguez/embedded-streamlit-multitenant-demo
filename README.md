# Embedded Streamlit Multitenant Demo

This is based on a [demo multitenant
repository](https://github.com/sfc-gh-rdominguez/snowflake-mutlitenant-patterns)
and serves as the basis for illustrating how to embed Streamlit applications
with [caller's
rights](https://docs.snowflake.com/en/developer-guide/streamlit/features/restricted-callers-rights)
when _not_ provisioning individual users in Snowflake. This is a common scenario
in multitenant applications as creating Snowflake users for every end user is
untenable and undesirable.

Instead of creating individual end users, a service user for each _tenant_ is
created. When a user logs in to the externally-hosted application (in this case,
on localhost), the IdP (also on localhost) mints a token containing tenant
information; that information is then parsed by the backend API and any sessions
or requests against Snowflake utilize this identity for tenant isolation.

Snowflake authenticates the sessions by utilizing an External OAuth integration,
mapping the `snowflake_user` and `scp` claims to a `LOGIN_NAME` in Snowflake;
this `LOGIN_NAME` maps to a tenant's service user (e.g., `TENANT_DUFF_SVC`).

For embedded Streamlit applications, an `EMBED_URL`, which is a short-lived
pre-signed URL, must be generated by the backend API. In this example, when a
user logs in and navigates to the page containing the iframe for the Streamlit
application, the backend API uses their tenant token to resolve the URL and
utilize as the `src` attribute in the iframe.

## Getting Started

### Requirements

- Docker
- [`just`](https://github.com/casey/just)
- [Snow CLI](https://docs.snowflake.com/en/developer-guide/snowflake-cli/index)
- An [ngrok](https://ngrok.com) account with an authtoken and a **reserved
static domain

**NB: ngrok is the only somewhat painful piece here...you can get away with the
free tier. The service itself is required for tunneling the locally-running IdP
(Keycloack) to Snowflake, which requires an HTTPS connection for verifying JWKs
in the External OAuth integration.**

### Configure

Copy `.env.example` to `.env` and fill in:

- `NGROK_AUTHTOKEN` — your ngrok authtoken.
- `KEYCLOAK_PUBLIC_URL` — your reserved ngrok domain, e.g.
`https://your-name.ngrok-free.app`.
- `SNOWFLAKE_HOST` — your account host, e.g.
`myorg-myacct.snowflakecomputing.com`.

### Run

`just` is here to make your life easier. Instead of having to smash together
some shell scripts, you'll call the following recipes to provision objects, set
up containers, etc. It **just** (pun intended) makes life easier.

```sh
# <connection> should be a named connection from your Snow CLI's connections.toml
# Run these in order, one at a time

# This runs the migrations against your Snowflake account and deploys the
# Streamlit app to Snowflake
just setup <connection>

# Bring up your IdP instance and seed it with tenants and users
just idp-up
just idp-seed
just idp-add-users

# Next, provision the External OAuth integration in Snowflake
just oauth-add <connection>

# Then, bring up the externally-hosted app
just app-up
```

Once the stack is up, open Snowsight and navigate to the Apps pane in the
left-hand nav. Warm the Streamlit application by opening it _before_ you attempt
to open the externally-hosted app.

Now, you can open `http://localhost:8000` and log in as one of the
pre-provisioned users under either of the two tenants. Credentials can be found
in [the walkthrough](./docs/00_WALKTHROUGH.md). 

When you're done, you can stop your containers using `docker compose down`. If
you're completely spent and want to erase all the resources (local _and_ in
Snowflake), use the recipe `just teardown <connection>`.
